# 优惠券优化：设计、坑与验证

## 为什么不能"相信券的名字"

麦当劳 MCP 返回的券里，**适用范围经常是不透明的**。一个典型样本：

```json
{ "couponId": "SC001", "couponCode": "MCD30R5", "name": "满30元减5元",  "minAmount": 30, "discountAmount": 5 }
{ "couponId": "SC005", "couponCode": "COFFEE50", "name": "咖啡类5折" }
{ "couponId": "SC003", "couponCode": "BIGMAC8",  "name": "巨无霸立减8元", "productCodes": ["1001"], "discountAmount": 8 }
```

- 第一张：门槛 + 减免都在 → 整单满减，能算
- 第三张：有 `productCodes` → 商品券，能算
- **第二张：只有一个名字。** 你没法从接口里知道它到底能打哪些商品、能不能叠加

## 判错的方向性代价（这是本模块的核心设计依据）

同一个判断错误，两个方向的代价完全不对称：

| 误判 | 后果 | 严重程度 |
|---|---|---|
| 整单券 → 当成商品券 | 少算优惠，用户看到的价偏高 | 可接受（保守） |
| 品类券 → 当成整单券 | 「咖啡类5折」变成整单 5 折，**¥59.50 被压到 ¥28.75** | 不可接受（虚假结论） |

> 这个 bug 在本项目开发过程中真实出现过。当时的估算把整单打了 5 折，
> 看起来"省了 ¥31.75"，实际下不了单。修法与回归测试见
> `scripts/selftest.mjs` 的「券作用域判定（回归）」分组。

**结论：所有不确定的判断一律往保守方向倒。**

## 作用域判定规则（`normalizeCoupons`）

```
有 productCodes            → product（商品券）
无 productCodes 但有门槛    → order  （整单券，满减本质作用于订单小计）
无 productCodes 无门槛
  但只有折扣率              → product + uncertain=true  ← 不参与本地搜索
其余                        → product（通配单品券）
```

`uncertain=true` 的券**不参与本地估价**，因为本地无从推断它该落在哪一行。
硬猜只会产出"把咖啡券配到甜筒上"这种荒唐组合。

## 那这些券怎么办：拿官方接口当探针

不猜，去问。`calculate-price` 本身就是最权威的"这张券能不能用"的裁判：

```
对每张 uncertain 券 × 购物车每一行：
    构造「只在该行挂这张券」的 items
    → calculate-price
    → 对比原价
       变便宜了  = 这张券真的作用在这一行，且省了多少是官方说的
       没变化    = 用不了
```

成本是 `O(uncertain 券数 × 行数)` 次调用，默认上限 8 次（`--max-probes` 可调）。

这是本项目相对"薄封装 Skill"的实质差异：**把接口的不透明性当成一个可以被实验解决的问题，
而不是靠猜或靠写死。**

## 两段式架构

```
第一段（本地，快，可能不准）
  DFS 剪枝搜索 → Top-K 候选方案
  作用：把搜索空间压到可核价的规模，避免盲目试

第二段（远端，慢，权威）
  逐个候选交给 calculate-price 真实算价
  作用：给出唯一可信的金额
```

**两段的输出绝不混排。** 只要拿到了真实核价结果，就只展示核价过的方案；
一个都没核成，才退回展示本地估算，并明确标注「上限 · 未核价」。

混排的后果是用户分不清哪个数字能信 —— 那还不如不给数字。

## 叠加语义

本地搜索遵循：

- 同一行最多挂 1 张商品券
- 同一张券只能用一次
- 整单券最多 1 张，作用于「商品券折后」的小计，门槛也按该小计判断
- 商品券与整单券是两张不同的券，**允许叠加**

真实平台是否允许叠加、门槛按折前还是折后算，各活动不一样。
所以本地结果只是**优惠上限**，真实可用性由 `calculate-price` 裁决。
这个语义被 `selftest.mjs` 的「单品券 + 整单券可叠加」用例锁住。

## 验证

```bash
node scripts/selftest.mjs
```

关键一项是**优化器 vs 暴力枚举的交叉验证**：对 300 组固定种子的随机
（购物车 1~3 行 × 券 1~4 张）实例，把 DFS 剪枝搜索的结果与"枚举每张券的
全部归宿（不用 / 挂某行 / 作整单券）"的暴力解逐一比对，必须完全一致。

没有这项测试，"剪枝"和"少搜了"看起来是一回事。
